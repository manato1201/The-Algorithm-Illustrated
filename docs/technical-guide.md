## 0. プロジェクト概要

**状態分離型 インタラクティブ・アルゴリズム図鑑**(The Algorithm Illustrated)は、367種類のアルゴリズムを「なぜ生まれ、どう動き、どこで報われるのか」という観点で解説する学習用Webアプリです。多くの記事には状態遷移を1ステップずつ再生・巻き戻しできる可視化が付属し、各記事の末尾にはPython/TypeScript/C++/Rust/C#の5言語による実装例を掲載しています。個人の学習用に継続開発している非商用プロジェクトです。

- **公開URL**: [the-algorithm-illustrated.vercel.app](https://the-algorithm-illustrated.vercel.app)
- **リポジトリ**: [github.com/manato1201/The-Algorithm-Illustrated](https://github.com/manato1201/The-Algorithm-Illustrated)

## 2. データモデル

### 2.1 frontmatterスキーマ

```yaml
---
name: バブルソート # 表示名
category: ソート # CATEGORY_TAXONOMYのcategoryのいずれか
subcategory: 比較ベース # 同カテゴリのsubcategoriesのいずれか
complexity: O(n²) # 最悪計算量(時間)の目安。バッジ表示に使用
summary: 隣接要素の比較・交換を繰り返す最も素朴な手法。... # カタログ一覧・検索対象の要約文
---
```

### 2.2 本文の見出し構成

全367件が次の4見出しで統一されています(可視化未対応の一部初期記事を除き、実質すべて充実化済み)。

1. `## 概要` — 何を解決するアルゴリズムか
2. `## 仕組み` — 動作原理の説明
3. `## 特性・トレードオフ` — 計算量の詳細(最悪/平均/最良)・長所短所・関連アルゴリズムへのリンク
4. `## 実装例` — Python → TypeScript → C++ → Rust → C#の順でコードフェンス(2026-08-04時点で367件全てに存在)

### 2.3 読み込み(`src/lib/content/algorithms.ts`)

| 関数                     | 用途                                                        |
| ------------------------ | ----------------------------------------------------------- |
| `getAllAlgorithmIds()`   | ファイル名一覧を返す(`generateStaticParams`用)              |
| `getAllAlgorithmsMeta()` | frontmatterのみの軽量版(カタログ一覧用、本文はHTML化しない) |
| `getAlgorithmDetail(id)` | frontmatter + 本文を`marked`でHTML化して返す(詳細ページ用)  |

### 2.4 コードブロック描画のカスタムレンダラー

`marked`のデフォルトには言語ラベル表示機能がないため、モジュールスコープでコードブロック用のカスタムrendererを登録している(`src/lib/content/algorithms.ts`)。

```
<div class="codeBlock">
  <div class="codeLangLabel">Python</div>
  <pre><code class="language-python">...</code></pre>
</div>
```

対応するCSSは`src/app/algorithms/[id]/page.module.css`に`:global()`エスケープ経由で定義(生成HTMLがCSS Modulesのスコープ外にあるため)。

## 4. 可視化アーキテクチャ

可視化対応済みは367件中**190件**(約52%)。`src/lib/has-visualizer.ts`の`hasVisualizer(id)`が、以下8種のビジュアライザいずれかにIDが登録されているかで判定する(ビルド時にも実行され、カタログの「可視化対応」バッジ・絞り込みチップに反映)。

| コンポーネント          | 描画方式           | 主な対象                                                         |
| ----------------------- | ------------------ | ---------------------------------------------------------------- |
| `SortVisualizer`        | Canvas(棒グラフ)   | ソート23種                                                       |
| `PathfindingVisualizer` | Canvas(グリッド)   | BFS/DFS/Dijkstra/A*/迷路生成/セルオートマトン等                  |
| `SearchVisualizer`      | Canvas(配列/地形)  | 配列探索・数値反復法・局所探索                                   |
| `GraphVisualizer`       | Canvas(頂点/辺)    | グラフ・木構造の一部・ゲーム木・オートマトン(最多カテゴリを吸収) |
| `DPTableVisualizer`     | HTML+CSS(表)       | 動的計画法・一部の反復アルゴリズム                               |
| `TreeVisualizer`        | Canvas(木構造)     | BST/AVL木/赤黒木/Treap/スプレー木/区間木                         |
| `TrieVisualizer`        | Canvas(トライ木)   | トライ木・Aho-Corasick法                                         |
| `StringMatchVisualizer` | Canvas(文字列照合) | KMP法/ラビン-カープ法/Z algorithm/ボイヤー・ムーア法/連長圧縮    |

## 5. 実装例(5言語コード)アーキテクチャ

367件全てに`## 実装例`セクション(Python/TypeScript/C++/Rust/C#)を実装済み(2026-07-14着手、2026-08-04完了、計1835スニペット)。

### 5.1 検証方法(言語ごとに異なる、環境制約への対応)

| 言語       | 検証方法                                                                                                                                                          |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Python     | `python3`で実際に実行し、既知の正解値・brute-force参照実装・独立実装した参照計算と突き合わせ                                                                      |
| TypeScript | `node --experimental-strip-types`で実際に実行し、Pythonと同じテストケースで検証                                                                                   |
| C#         | スクラッチの`dotnet new console`プロジェクトを作り`dotnet run`で実行検証                                                                                          |
| C++ / Rust | **環境にコンパイラ非搭載**のため実行検証不可。検証済みロジックを1行ずつ手動レビューし、特に配列境界(空配列・要素数0/1)とRustの`usize`アンダーフローに注意して移植 |

### 5.2 検証中に発見・修正された実バグの例

- **smooth-sort**: 子ノード位置計算式が`leonardo(order-2)`になっていたが正しくは`leonardo(order-1)`(次数3以上の木が形成される要素数=概ね13要素以上で初めて破綻)
- **suffix-tree-ukkonen**: rule 3(早期終了)分岐で接尾辞リンク設定条件が誤っており、rootを経由するリンクが未設定のままPythonの負インデックス仕様で誤ったノードを書き換えていた
- **dfa-minimization**: 最小化後DFAの開始状態インデックスを固定値0と仮定していたが、分割クラスの並び順によって変わり得るため`start`フィールドを明示的に追跡する形に修正
- ロシア農民の乗算(TypeScript): `<<`/`>>`演算子によるJSの32bit切り詰めで`b`が2^31を超えると結果が破綻する問題を`Math.floor`/`*2`演算に置換して解消

### 5.3 Rustの設計方針

赤黒木・スプレー木・van Emde Boas木・two-three-treeなど、親子ポインタを持つ木構造は`Rc<RefCell<>>`によるポインタベース実装だと手動レビューでの正しさ検証が困難なため、意図的に**アリーナ(Vec+インデックス)ベース設計**に置き換えている。
