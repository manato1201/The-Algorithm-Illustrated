## 概要

株価スパン問題(Stock Span Problem)は、日々の株価の系列が与えられたとき、各日について「その日の株価以下の価格が、何日前まで連続して続いていたか(その日を含む)」というスパン(span)を、全ての日について求める問題である。素朴には各日ごとに過去を逆順に見ていけばO(n²)かかるが、**「今日の株価以下だった過去の日は、二度と将来の答えの計算に必要にならない」**という性質に気づき、それを貪欲に切り捨てていく単調スタック(monotonic stack)を使うことで、全体をO(n)で計算できる。

「過去のデータをどこまで遡って比較する必要があるか」を、後から使われないと分かった時点で即座に(貪欲に)捨ててしまうという発想は、ヒストグラム内最大長方形問題や「次に大きい要素(Next Greater Element)」問題など、多くのスタックベースのO(n)アルゴリズムに共通する基本パターンであり、貪欲法の一種として位置づけられる。

## 仕組み

1. 「(株価, インデックス)」の組を積む、空のスタックを用意する
2. 株価の系列を先頭から順に処理する。各日`i`(価格`p[i]`)について:
   - スタックの先頭にある要素の価格が`p[i]`以下である間、**その要素をスタックから貪欲に取り除く**(その要素は、今日以降どの未来の日のスパン計算にも二度と必要にならないため、捨てて構わない)
   - 取り除いた後のスタックが空なら、スパンは`i + 1`(先頭から今日まで全て今日以下だったことになる)。空でなければ、スタックの新しい先頭のインデックスを`j`として、スパンは`i - j`
   - `(p[i], i)`をスタックに積む
3. 全ての日を処理し終えたら、各日のスパンの配列が答えになる

**なぜ「今日以下の過去の要素を捨てる」ことが安全な貪欲判断なのか**: ある過去の日`k`の株価が今日の株価`p[i]`以下だったなら、`k`より未来のどの日`m`(`m > i`)についても、`p[m] ≥ p[i] ≥ p[k]`が成り立つ限り`k`は`m`のスパン計算の「壁」にはなり得ない——なぜなら`k`より後に来る`i`の存在自体が、`m`から見て`k`まで遡る前に必ず`p[m]`より高い価格(あるいは同じ判定を行う`i`)に先に当たるからだ。つまり`k`は今後の任意の判定において`i`によって完全に「覆い隠される」ため、二度と最終的な答えに影響しない。この「一度不要と分かった要素は、以後の判定に一切関与しないので捨ててよい」という保証があるからこそ、各要素はスタックに高々1回積まれ高々1回取り除かれるだけで済み、貪欲な削除の総回数が全体でO(n)に抑えられる。

**具体例で追う**: 株価`[100, 80, 60, 70, 60, 75, 85]`を先頭から処理する(スタックには価格のみ表記):

| 日 `i` | 価格 `p[i]` | 処理前のスタック(上が先頭) | 貪欲に捨てる要素 | 処理後のスタック | スパン |
|---|---|---|---|---|---|
| 0 | 100 | `[]` | なし | `[100]` | 1 |
| 1 | 80 | `[100]` | なし(100 > 80) | `[100, 80]` | 1 |
| 2 | 60 | `[100, 80]` | なし(80 > 60) | `[100, 80, 60]` | 1 |
| 3 | 70 | `[100, 80, 60]` | `60`(60 ≤ 70) | `[100, 80, 70]` | 2 (`3 - 1`) |
| 4 | 60 | `[100, 80, 70]` | なし(70 > 60) | `[100, 80, 70, 60]` | 1 |
| 5 | 75 | `[100, 80, 70, 60]` | `60`, `70`(いずれも ≤ 75) | `[100, 80, 75]` | 4 (`5 - 1`) |
| 6 | 85 | `[100, 80, 75]` | `75`, `80`(いずれも ≤ 85) | `[100, 85]` | 6 (`6 - 0`) |

7日間で捨てられた要素の総数(4回)は積まれた要素の総数(7回)を超えず、全体としてスタック操作の回数がO(n)に収まっていることがこの表からも確認できる。

## 特性・トレードオフ

- **計算量**: O(n)。各日の株価はスタックに高々1回プッシュされ、高々1回ポップされるため、一見「各日についてスタックを見る」という操作を繰り返しているように見えても、ポップの総回数はn回を超えない(ならし解析・amortized analysis)。素朴なO(n²)解(各日から過去を逐一見る)に対する明確な改善
- **貪欲な削除の局所最適性と大域最適性の一致**: この手法における「貪欲な判断」は各要素をスタックから捨てるかどうかの1点に集約される。「今日以下の株価を持つ過去の要素は、今この瞬間は不要に見えるだけでなく、未来永劫どの日の計算にも決して必要にならない」ことが前述の理由で保証されているため、局所的に「今回不要」と判断して捨てる操作が、常に大域的にも正しい(取り消しが必要になることが絶対にない)。これは貪欲法が安全である典型的な条件——「一度捨てた選択肢が、後になって最適解に必要だったと判明することがない」——を満たす好例であり、この保証がなければ(例えば「株価がわずかでも下がった日だけを捨てる」といった誤った基準を使えば)後の計算で誤ったスパンを出してしまう反例が容易に作れる
- **単調スタックという一般パターンの一例**: 「次に大きい要素を求める(Next Greater Element)」「ヒストグラム内の最大長方形」「気温の日数差(Daily Temperatures)」など、多くの一次元配列に対するO(n)アルゴリズムが同じ「単調性を保つようにスタックから貪欲に要素を捨てる」構造を持つ。株価スパン問題はこのパターンの中でも特に典型的な入門例として扱われる
- **「直前でより高い株価の日」問題との表裏関係**: スパンは実質的に「今日より前で、今日より高い株価が最後に出た日」からの経過日数を求めていることと等価であり、これは「Previous Greater Element(直前でより大きい要素)」という別の古典的なスタック問題そのものである。単調スタックの向き(増加を保つか減少を保つか)と、探索する方向(前方か後方か)の組み合わせを変えるだけで、Next Greater Element・Previous Greater Element・株価スパンなど見た目の異なる複数の問題が同じ実装パターンに帰着する
- **オンライン処理との相性**: このアルゴリズムは未来の株価を先読みする必要がなく、新しい日の株価が届くたびにその場でスパンを1つ確定できる(オンラインアルゴリズム)。株価のストリームをリアルタイムに処理するダッシュボードのように、全データが揃う前に結果を出したい用途と相性がよい
- **使いどころ**: 金融データにおけるトレンド継続日数の可視化、時系列データでの「直近ピーク更新までの連続日数」の計算、ヒストグラムや気温データなど単調スタックが使える他の多くの時系列解析問題への応用の第一歩

## 実装例

```python
def stock_span(prices: list[int]) -> list[int]:
    spans = [0] * len(prices)
    stack: list[int] = []  # 株価が単調減少になるようインデックスを積むスタック

    for i, price in enumerate(prices):
        while stack and prices[stack[-1]] <= price:
            stack.pop()  # もう二度と使われない過去の日を貪欲に捨てる
        spans[i] = i + 1 if not stack else i - stack[-1]
        stack.append(i)

    return spans


if __name__ == "__main__":
    prices = [100, 80, 60, 70, 60, 75, 85]
    print(stock_span(prices))  # [1, 1, 1, 2, 1, 4, 6]
```

```typescript
function stockSpan(prices: number[]): number[] {
  const spans = new Array<number>(prices.length).fill(0);
  const stack: number[] = []; // 株価が単調減少になるようインデックスを積むスタック

  for (let i = 0; i < prices.length; i++) {
    const price = prices[i];
    while (stack.length > 0 && prices[stack[stack.length - 1]] <= price) {
      stack.pop(); // もう二度と使われない過去の日を貪欲に捨てる
    }
    spans[i] = stack.length === 0 ? i + 1 : i - stack[stack.length - 1];
    stack.push(i);
  }

  return spans;
}

// 例: [100, 80, 60, 70, 60, 75, 85] -> [1, 1, 1, 2, 1, 4, 6]
console.log(stockSpan([100, 80, 60, 70, 60, 75, 85]));
```
