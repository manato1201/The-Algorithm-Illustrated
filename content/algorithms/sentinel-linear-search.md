## 概要

[線形探索](/algorithms/linear-search)の最もナイーブな実装は、ループの各反復で「(1)現在の要素が目的値と一致するか」と「(2)まだ配列の範囲内か」という2つの条件を毎回チェックする。この計算量オーダー自体はO(n)のままだが、n回のループそれぞれで2回ずつ比較が発生する分、定数倍のオーバーヘッドが積み重なる。番兵法(Sentinel Linear Search)は、配列の末尾に探索対象の値そのものを一時的に「番兵(sentinel)」として置いておくことで、「範囲内かどうか」のチェックを丸ごと省略し、「一致するかどうか」のチェック1つだけで済ませる古典的な最適化テクニックである。番兵を置いておけば、たとえ本来の配列内に目的値が存在しなくても必ず番兵の位置で一致が起きるため、ループが配列の外へはみ出す心配がなくなる。

## 仕組み

1. 探索対象の配列の末尾(通常は元の配列を1つ拡張した位置、あるいは末尾要素を一時退避した位置)に、探索したい値`target`自体を「番兵」として書き込む
2. インデックス0から順に、`arr[i] == target`かどうかだけを調べるループを回す。「`i`が配列の範囲内か」のチェックは行わない
3. 番兵のおかげで、本来の配列内に`target`が存在しなくても、必ずどこかの位置(遅くとも番兵の位置)で一致が起き、ループは自然に停止する
4. ループが停止したインデックス`i`が「元の配列の末尾より前」であれば本物のヒット、「番兵の位置と一致」であれば元の配列には存在しなかったと判定する
5. 配列を書き換えて番兵を置いた場合は、探索終了後に元の末尾要素を復元する(呼び出し元から見て配列の内容を変えないようにする配慮)

このテクニックの本質は「ループの継続条件を1つ減らす」ことにある。CPUのループでは分岐(条件判定)そのものにコストがかかるため、n回の反復で2n回だった比較をn+1回程度まで減らせれば、要素数が大きい場合に無視できない高速化になる。ただし、この最適化はあくまで低レイヤーの定数倍改善であり、探索対象がソート済みであれば[線形探索](/algorithms/linear-search)ではなく[二分探索](/algorithms/binary-search)を使う方がアルゴリズム的に本質的に高速である点には注意が必要。

## 特性・トレードオフ

- **計算量**: 最悪・平均ともにO(n)で、[線形探索](/algorithms/linear-search)とオーダーは変わらない。あくまでループ内の比較回数を約半分に減らす定数倍の最適化であり、漸近的な改善ではない
- **配列の書き換えが必要**: 番兵を置くには配列の末尾に余分な1要素分の領域が必要になる(あるいは末尾要素を一時退避してから書き戻す)。読み取り専用の配列や、他のスレッドから同時に参照される配列には安全に適用できない場合がある
- **効果は言語・実行環境に依存する**: 現代の最適化コンパイラやJITは単純なループの境界チェックを自動的に融合・削除できることが多く、高級言語では手動での番兵法によるゲインが実測ではほとんど出ないこともある。C言語のような低レベルな環境や、極めて頻繁に呼ばれるホットループでは依然として意味を持つ
- **[線形探索](/algorithms/linear-search)との関係**: アルゴリズムとしての本質(先頭から順に1つずつ調べる)は[線形探索](/algorithms/linear-search)と全く同じで、番兵法はその実装を最適化する付随的なテクニックという位置づけである
- **使いどころ**: 組み込み機器やゲームエンジンの内部処理のように、線形探索が極めて頻繁に呼ばれ、かつ配列を一時的に書き換えても問題ない状況でのマイクロ最適化。通常のアプリケーション開発では可読性を優先して素直な[線形探索](/algorithms/linear-search)で十分なことが多い

## 実装例

```python
from typing import List


def sentinel_linear_search(arr: List[int], target: int) -> int:
    n = len(arr)
    if n == 0:
        return -1

    last = arr[n - 1]  # 末尾要素を退避しておく
    arr[n - 1] = target  # 番兵として書き込む

    i = 0
    while arr[i] != target:
        i += 1  # 境界チェックが不要。番兵のおかげで必ずどこかで止まる

    arr[n - 1] = last  # 配列を元の状態に復元する

    if i < n - 1 or last == target:
        return i
    return -1  # 番兵の位置で止まり、かつ末尾要素も一致しなかった=見つからない
```

```typescript
function sentinelLinearSearch(arr: number[], target: number): number {
  const n = arr.length;
  if (n === 0) return -1;

  const last = arr[n - 1]; // 末尾要素を退避しておく
  arr[n - 1] = target; // 番兵として書き込む

  let i = 0;
  while (arr[i] !== target) {
    i++; // 境界チェックが不要。番兵のおかげで必ずどこかで止まる
  }

  arr[n - 1] = last; // 配列を元の状態に復元する

  if (i < n - 1 || last === target) {
    return i;
  }
  return -1; // 番兵の位置で止まり、かつ末尾要素も一致しなかった=見つからない
}
```
