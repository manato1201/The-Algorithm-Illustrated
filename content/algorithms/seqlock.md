## 概要

読み取りが書き込みよりも圧倒的に多いデータ(オペレーティングシステムのタイムスタンプカウンタなど)に対しては、[readers-writers-problem](/algorithms/readers-writers-problem)の一般的な解法(リーダー用のロックを取る)であってもオーバーヘッドが無視できない場合がある。シーケンスロックは、このような状況に特化した楽観的な同期機構である。読み取り側にはロック取得のコストを一切課さない代わりに、「読み取っている最中にデータが書き換わっていたら、読み直す」という戦略をとる。共有の整数カウンタ(シーケンス番号)を用意し、書き込みの開始と終了のたびにこのカウンタを更新する——読み取り側は、読み取りの前後でこのカウンタの値を比較するだけで、途中に書き込みが割り込まなかったことを検証できる。Linuxカーネルの時刻管理機構(`jiffies`や`ktime`)などで実際に使われている、軽量な同期プリミティブである。

## 仕組み

1. 共有のシーケンスカウンタ`seq`を0で初期化する(偶数=安定状態、奇数=書き込み中を表す)
2. **書き込み**: 書き込み開始時に`seq`をインクリメントする(必ず奇数になる)。続けてデータを更新し、更新が終わったら再度`seq`をインクリメントする(必ず偶数に戻る)。複数のライターが同時に書き込まないよう、書き込み自体は別途スピンロックなどで直列化しておく
3. **読み取り開始**: `seq`を読み取り、値を`s1`として保存する。もし`s1`が奇数であれば、ちょうど書き込みの最中なので少し待ってから読み取りをやり直す
4. **データの読み取り**: 保護対象のデータを読み取る
5. **読み取り終了**: 再度`seq`を読み取り`s2`とする。`s1`と`s2`が一致していれば(そして偶数であれば)、読み取り中に書き込みが割り込まなかったことが保証されるので、読み取った値は正しい。一致しなければ手順3からやり直す

## 特性・トレードオフ

- **計算量**: 競合がなければO(1)。書き込みと重なった場合のみ読み取り側がリトライし、実行時間が延びる
- **書き込み優先という設計思想**: ライターは読み取り側の存在を一切気にせず、常に即座に書き込める。読み取りが頻発してもライターが飢餓することはない。逆に書き込みが極端に頻発する状況では、読み取り側が常にリトライさせられ続け、実質的に進行できなくなる可能性がある
- **適用条件の制約**: シーケンスロックで安全に保護できるのは、「読み取り中に一時的に矛盾した値を読んでも、単に再試行すれば実害がない」データに限られる。ポインタを含む複雑な構造体や、読み取り中の不整合な値をそのまま参照外しするような操作には、追加の注意深い設計が必要になる
- **[readers-writers-problem](/algorithms/readers-writers-problem)との違い**: 通常のリーダーライターロックはリーダー同士も内部的な同期コストを払うのに対し、シーケンスロックのリーダーは共有カウンタへの書き込みを一切行わず、読み取りと比較だけで完結する。この非対称さが、高頻度な読み取りに対する著しい低オーバーヘッドを生む
- **使いどころ**: Linuxカーネルのタイムキーピング機構、高頻度に参照される小さな統計情報の共有、読み取りがクリティカルパス上にある低レイテンシシステム

## 実装例

```python
import threading


class SeqLock:
    def __init__(self) -> None:
        self.seq = 0
        self._write_lock = threading.Lock()  # ライター同士の直列化(実機では別途スピンロック等が必要)
        self._data = 0

    def write(self, value: int) -> None:
        with self._write_lock:
            self.seq += 1  # 奇数にする: 書き込み中であることを示す
            self._data = value
            self.seq += 1  # 偶数に戻す: 書き込み完了を示す

    def read(self) -> int:
        while True:
            s1 = self.seq
            if s1 % 2 == 1:
                continue  # 書き込み中なのでリトライ
            value = self._data
            s2 = self.seq
            if s1 == s2:
                return value  # 読み取り中に書き込みが割り込まなかった
            # 読み取り中に書き込みが割り込んだのでリトライ
```

```typescript
class SeqLock {
  seq = 0;
  private data = 0;

  // ライター同士の直列化: 実機では別途スピンロック等が必要
  write(value: number): void {
    this.seq += 1; // 奇数にする: 書き込み中であることを示す
    this.data = value;
    this.seq += 1; // 偶数に戻す: 書き込み完了を示す
  }

  read(): number {
    for (;;) {
      const s1 = this.seq;
      if (s1 % 2 === 1) continue; // 書き込み中なのでリトライ
      const value = this.data;
      const s2 = this.seq;
      if (s1 === s2) return value; // 読み取り中に書き込みが割り込まなかった
      // 読み取り中に書き込みが割り込んだのでリトライ
    }
  }
}
```
