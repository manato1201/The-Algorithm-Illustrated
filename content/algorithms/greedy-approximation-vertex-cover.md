## 概要

頂点被覆問題(Vertex Cover)は「グラフの全ての辺について、少なくとも一方の端点が含まれるように、できるだけ少ない頂点集合を選べ」という問題であり、厳密な最小頂点被覆を求めることはNP困難であることが知られている。したがって大規模なグラフに対して厳密な最適解を効率よく求めるアルゴリズムは(P≠NPと信じられている限り)存在しない。

ところが「**まだどの端点も被覆に選ばれていない辺を1本適当に選び、その両端点を被覆に加える**」という驚くほど単純な貪欲法だけで、常に**最適解の高々2倍のサイズ**という近似保証を持つ解が得られる。近似アルゴリズムの入門で必ず取り上げられる代表例であり、「厳密解は求まらなくても、理論的に品質が保証された近似解なら効率よく求まる」ことを示す好例になっている。

似た名前の「次数の最大な頂点を毎回貪欲に選ぶ」という別の戦略もよく知られているが、こちらは実装がやや複雑な上に近似保証の係数が`O(log n)`程度までしか改善できず、この記事で扱う「辺を1本選んで両端点を加える」方式の方が実装は単純でありながら定数倍(2倍)という強い保証を持つ点で対照的である。

## 仕組み

1. 被覆済みの頂点集合`C`を空集合で初期化する
2. グラフの辺集合`E`の中から、**両端点がまだ`C`に含まれていない辺**(まだ被覆されていない辺)を1本選ぶ
3. その辺の両端点`(u, v)`を**両方とも**`C`に追加する(片方だけでなく両方追加するのが重要な点)
4. 被覆されていない辺がなくなるまで、2〜3を繰り返す
5. `C`が頂点被覆の解となる

「片方の端点だけを選ぶ」のではなく「両端点を無条件に選ぶ」という一見無駄に見える選び方こそが、後述する2近似保証の証明の鍵になる。

**具体例で追う**: 頂点`{1,2,3,4,5}`、辺`{(1,2), (2,3), (3,4), (4,5)}`(パスグラフ)を考える。最初に辺`(2,3)`を選ぶと`C = {2,3}`になり、この時点で`(1,2)`と`(3,4)`も被覆済みになる。残る未被覆の辺は`(4,5)`だけなので、これを選んで`C = {2,3,4,5}`となり終了する。しかし実際の最小頂点被覆は`{2,4}`(サイズ2)で足りる——`(1,2)`と`(2,3)`は頂点2で、`(3,4)`と`(4,5)`は頂点4で被覆できるからだ。貪欲法の出力サイズ4は最適解サイズ2のちょうど2倍であり、この単純な例だけでも近似係数`2`がタイトに現れることが確認できる。

## 特性・トレードオフ

- **NP困難な問題への保証された近似**: 最小頂点被覆を厳密に求める問題はNP困難であり、多項式時間での厳密解法は知られていない。しかしこの貪欲法は多項式時間(O(V+E))で、最適解のサイズを`OPT`としたとき高々`2・OPT`個の頂点で必ず被覆できることが証明されている。「局所最適(1本の辺を貪欲に処理しているだけ)であっても、大域的な近似保証がつく」という好例
- **なぜ2近似になるのか(証明の骨子)**: アルゴリズムが選ぶ辺は互いに端点を共有しない(マッチング)。なぜなら、一度選んだ辺の端点は次にその頂点を含む辺が候補から除外されるためだ。選んだ辺の本数を`m`とすると、これら`m`本の辺は互いに素なので、最適解はこの`m`本の辺それぞれについて少なくとも1つの端点を含まなければならず、`OPT ≥ m`が成り立つ。一方アルゴリズムの出力サイズは`2m`(各辺から両端点を選ぶため)なので、`|C| = 2m ≤ 2・OPT`となる
- **反例(貪欲法が最適から乖離するケース)**: 辺を選ぶ順序次第では、実際に2倍に近い無駄が生じる。たとえば星グラフ(中心1点から`k`個の葉に辺が伸びる)なら最小頂点被覆は中心の1点だけで済むが、この貪欲法がたまたま葉の側の辺を先に選ぶと、選んだ辺ごとに葉と中心の両方を被覆に加えてしまい、非効率な選択になりうる(星グラフ自体は結果的に中心を含む辺が最終的に全て消えるため実害は小さいが、一般のグラフでは選ぶ順序によって2倍に近い無駄な頂点を選んでしまう構成が存在する)。これが「局所的には合理的な選択が、大域的には最適から最大2倍まで乖離しうる」ことの具体例であり、近似保証の`2`という係数がタイトである(それ以上には改善できない構成が存在する)ことの根拠にもなっている
- **極大マッチングとの関係**: このアルゴリズムが選ぶ辺の集合は、実は「極大マッチング(これ以上辺を追加できないマッチング)」そのものになっている。極大マッチングの辺数を`m`とすると`OPT ≥ m`が成り立つ(前述の証明)一方、任意の極大マッチングから両端点を全て選べば必ず頂点被覆になるという事実は、頂点被覆問題とマッチング問題という一見別の組合せ最適化問題が、近似アルゴリズムの文脈で密接に結びついていることを示している
- **独立集合との表裏関係**: グラフの頂点集合`V`から頂点被覆`C`を除いた残り`V \ C`は、必ず独立集合(どの2頂点も辺で結ばれていない集合)になる。したがって「最小頂点被覆を求める」ことと「最大独立集合を求める」ことは表裏一体の問題だが、最大独立集合には(頂点被覆と違って)定数近似アルゴリズムが存在しないことが知られており、同じコインの裏表でも近似可能性が全く異なるという興味深い非対称性がある
- **LP緩和による2近似との比較**: 頂点被覆問題を線形計画問題として緩和し(各頂点に0〜1の実数を割り当て、辺の両端点の値の和が1以上という制約のもとで合計を最小化)、得られた解を0.5以上なら1、未満なら0に丸める、という別の2近似アルゴリズムも知られている。理論的な近似係数はこの記事の貪欲法と同じ2だが、LPを解く必要がある分だけ計算コストは高く、「辺を1本ずつ選ぶだけ」という貪欲法の実装の単純さが際立つ
- **重み付き版への拡張**: 各頂点にコスト(重み)が付いている場合の重み付き頂点被覆問題に対しても、LP緩和と丸めの手法を使えば同様に2近似が得られることが知られている。ただし本記事の「辺の両端点を無条件に加える」という単純な貪欲法は、重みを考慮しない一様なコストの場合にのみ2近似が保証される点に注意が必要で、重み付きの場合に同じ手続きをそのまま適用しても近似保証は一般に崩れる
- **パラメータ化計算量の観点**: 頂点被覆問題はNP困難だが、「解のサイズ`k`が小さい」という条件を付けると、`k`に対して指数的・全体の頂点数`n`に対して多項式という計算量(FPT: Fixed-Parameter Tractable)で厳密解を求めるアルゴリズムが存在する。この記事の貪欲法はどんな`k`でも多項式時間で動く近似アルゴリズムである一方、パラメータ化アルゴリズムは`k`が小さいときに限り厳密解を保証するという、異なる方向からのアプローチとして対比できる
- **使いどころ**: ネットワークのモニタリング(全てのリンクを監視するために、できるだけ少ない観測点をどのノードに置くか)、生物情報学での相互作用ネットワーク解析、[貪欲集合被覆](/algorithms/set-cover-greedy)と並んで「NP困難な被覆・彩色系の問題に対して、単純な貪欲法がどこまで良い近似保証を持てるか」を学ぶ最初の教材として広く使われる

## 実装例

```python
def greedy_vertex_cover(edges: list[tuple[int, int]]) -> set[int]:
    cover: set[int] = set()
    for u, v in edges:
        if u in cover or v in cover:
            continue  # どちらかの端点が既に被覆済みなら、この辺はすでに被覆されている
        cover.add(u)
        cover.add(v)
    return cover


def is_vertex_cover(edges: list[tuple[int, int]], cover: set[int]) -> bool:
    """全ての辺が被覆されているかを検証するヘルパー。"""
    return all(u in cover or v in cover for u, v in edges)


if __name__ == "__main__":
    # パスグラフ 1-2-3-4-5 の例
    edges = [(1, 2), (2, 3), (3, 4), (4, 5)]
    cover = greedy_vertex_cover(edges)
    print(cover)  # {2, 3, 4, 5} (最適解 {2, 4} の2倍に相当)
    assert is_vertex_cover(edges, cover)
```

```typescript
type Edge = [number, number];

function greedyVertexCover(edges: Edge[]): Set<number> {
  const cover = new Set<number>();
  for (const [u, v] of edges) {
    if (cover.has(u) || cover.has(v)) continue;
    cover.add(u);
    cover.add(v);
  }
  return cover;
}

function isVertexCover(edges: Edge[], cover: Set<number>): boolean {
  return edges.every(([u, v]) => cover.has(u) || cover.has(v));
}

// パスグラフ 1-2-3-4-5 の例
const edges: Edge[] = [
  [1, 2],
  [2, 3],
  [3, 4],
  [4, 5],
];
const cover = greedyVertexCover(edges);
console.log(cover); // Set(4) {2, 3, 4, 5} (最適解 {2, 4} の2倍に相当)
console.assert(isVertexCover(edges, cover));
```
